# 整合包工作台（Modpack Studio）实现计划

> 版本：2026-10-30  
> 定位：面向整合包作者的“导入 → 审计 → 策展 → 修改 → 导出”工作台。  
> 形态：独立核心 + 本地 Web UI + 启动器适配层。  
> 原则：先只读审计，再安全编辑；默认不改原包；每一步都能运行和验收。

---

## 1. 项目定位

不是“另一个启动器”，而是整合包的**策展工具**：

```text
导入整合包
  → 拆出 mod / 资源 / 配置
  → 读 jar 元数据
  → 对比 CurseForge / Modrinth 标签
  → 生成依赖 / 联动关系图（分类作为颜色与分组）
  → 手工补标签、启用/禁用、更新、卸载
  → 导出新整合包
```

核心不是树状图，而是四个模型：

1. **文件模型**：包里到底有哪些文件。
2. **标签模型**：这些 mod 属于什么类别，标签来自哪里，是否冲突。
3. **依赖图**：谁能单独存在，谁必须带前置，卸载/更新会破坏谁。
4. **联动图**：optional / incompatible / embedded 关系，以及“前置本身也是玩法模组”的情况。

### 为什么图优先

- 一个 mod 可以**既是前置，又是玩法模组**。例如 Create 被大量 addon 依赖，它本身也是核心玩法；树只能把它塞进一个分类节点，看不出它的枢纽地位。
- **联动关系是边，不是层级**。可选项、冲突、内置库、互相关联的 mod，用树表达会丢信息。
- 分类仍然重要，但降级为**颜色、分组和筛选条件**，不再作为唯一导航。
- 作者最想一眼看到的是：**谁依赖谁、谁是枢纽、哪些是孤立节点、哪些缺前置**。这正是图擅长的。

树状图保留为辅助视图（按分类折叠/筛选），但主视图是关系图。

## 2. 目标与非目标

### 目标

- 支持主流格式导入：CurseForge、Modrinth、MCBBS、MultiMC/Prism、HMCL、Server pack、packwiz、GDLauncher、裸 ZIP。
- 读取 jar 内的 `mods.toml` / `fabric.mod.json` / `quilt.mod.json` / `mcmod.info`。
- 从 CurseForge / Modrinth 拉取介绍、图标、分类、加载器、侧别、依赖。
- 生成可筛选的依赖/联动关系图、分类分组、问题清单。
- 安全地做启用/禁用、手工标签、改分类、卸载、更新、添加。
- 导出回原格式或指定格式。
- 单文件分发，可被启动器拉起或嵌入 WebView。

### 非目标（第一版不做）

- 不做游戏启动器本身（不负责下载原版、登录、启动游戏）。
- 不做 mod 热加载（改完必须重启游戏）。
- 不做云端账号/同步。
- 不做自动上传 CurseForge / Modrinth。
- 不做所有冷门格式；先覆盖文档里列出的主流格式。

---

## 3. 核心原则

1. **非破坏性**：所有编辑先落到 `work/` 工作副本；原包不动。
2. **可撤销**：每个操作记入 edit log，支持 undo/redo。
3. **依赖感知**：卸载/更新/添加必须先做影响分析。
4. **默认锁版本**：更新只“检查”，用户确认后才应用。
5. **来源可追溯**：每个标签、每个文件都标明来源（CF / Modrinth / 本地 / 手工）。
6. **失败可恢复**：网络失败、哈希不符、清单缺失时给明确提示，不静默跳过。
7. **单文件分发**：核心编译成一个二进制，Web UI 内嵌。

## 4. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 核心 | Go 1.27 | 单文件二进制、标准库 ZIP/JSON/HTTP 足够、Android/桌面都能跑 |
| 前端 | 原生 HTML/CSS/JS | 无构建链、可直接 embed、启动器 WebView 易接入 |
| TOML | `github.com/BurntSushi/toml` | pack.toml / mods.toml，成熟稳定 |
| 缓存 | 本地 JSON 文件 | 第一版不引入 SQLite；元数据按 key 缓存 |
| 打包 | `go:embed` + `go build` | 一个可执行文件 |
| 测试 | Go `testing` + 合成 ZIP | 不依赖真实整合包和网络 |

构建环境注意：

- 本机 `proxy.golang.org` 不可用，使用：

```sh
export GOPROXY=https://goproxy.cn,direct
export GOSUMDB=off
export GOTOOLCHAIN=local
```

## 5. 总体架构

```text
┌─────────────────────────────────────────────────────┐
│                    Web UI (embedded)                │
│  关系图 │ 分类筛选 │ 详情面板 │ 问题清单 │ 导出     │
└───────────────────────┬─────────────────────────────┘
                        │ HTTP / JSON
┌───────────────────────▼─────────────────────────────┐
│                   Core (Go binary)                  │
│                                                     │
│  pack  ── 格式识别、清单解析、ZIP 安全解压          │
│  jarmeta ── jar 元数据读取                          │
│  source ── CurseForge / Modrinth 客户端 + 缓存      │
│  tags  ── 来源标签 + 归一化 + 手工标签              │
│  graph ── 前置、前置的前置、反向依赖、冲突          │
│  edit  ── 工作副本、变更日志、撤销                  │
│  export ── 回写 CF / Modrinth / MCBBS / MultiMC     │
└─────────────────────────────────────────────────────┘
```

进程模型：

- `modpack-studio analyze <pack>`：只读，输出 JSON 或静态 HTML。
- `modpack-studio serve <pack>`：本地 HTTP 服务 + Web UI。
- 启动器用 `--pack <路径> --port 0 --no-browser` 拉起，读取返回的 URL。

### 6.4 项目文件

工作副本根目录放：

```text
work/
├── modpack-studio.json       # 项目元数据、标签覆盖、编辑记录
```

导出时只把 `pack/` 按目标格式重新打包；`modpack-studio.json` 不进入正式包（作为 sidecar 单独保存）。

## 9. P1 详细拆解

### 1-1 工程骨架

任务：

- `go.mod`，module `modpack-studio`。
- `internal/model`：Pack / Mod / Loader / Source / Dependency / Tag / Stats。
- `cmd/modpack-studio`：`analyze` / `sniff` 子命令。
- 错误处理约定：可恢复问题进 `warnings`，不可恢复返回 error。
- 测试：模型 JSON 序列化往返。

验收：

```sh
go test ./...
go build -o modpack-studio ./cmd/modpack-studio
./modpack-studio --help
```

### 1-2 格式识别 + 清单解析

任务：

- `Sniff(zip)` 按固定优先级识别，支持根目录和一层目录。
- 解析 CF / Modrinth / MCBBS / MultiMC / HMCL / Server / GDL。
- 裸 ZIP 兜底：识别 `mods/`、`overrides/`、`minecraft/`、`.minecraft/`。
- 记录 `format`、`base`、名称、版本、MC、加载器、远端文件。
- 对未知加载器、缺失字段给出 warning。

验收：

- 每种格式一个合成 ZIP 测试。
- `manifest.json` 带 `addons` 识别为 MCBBS，不带识别为 CurseForge。
- 一层目录嵌套也能识别。

### 1-3 jar 元数据

任务：

- Forge：`META-INF/mods.toml`、旧版 `mcmod.info`。
- NeoForge：`META-INF/neoforge.mods.toml`。
- Fabric：`fabric.mod.json`。
- Quilt：`quilt.mod.json`。
- 回退：jar 文件名、`META-INF/MANIFEST.MF`。
- 输出 modid、名称、版本、作者、描述、依赖、侧别。

验收：

- 合成 jar 测试每种元数据。
- 没有元数据的 jar 不崩溃，标记 `unknown`。

### 1-4 来源标签

任务：

- Modrinth：按 project/version 或 hash 查项目；取 categories/loaders/client_side/server_side。
- CurseForge：按 projectID/fileID 查；取 categories/classId；介绍走 description 端点。
- 中文译名：优先人工映射表（slug -> 中文），后续可接 MC百科；写入 `nameZh`，不覆盖英文原名。
- 缓存：key -> JSON，带 TTL。
- 失败降级：无 Key、限流、404 都不能中断整体分析。

验收：

- 无网络时仍能生成树，只是标签为空。
- 有网络时标签写入 `tags.source`。
- 每个 mod 可以有英文名 + 中文译名；缺失时只显示英文，不阻塞。

### 1-5 依赖图

任务：

- 节点：mod id（优先 modid，其次 source id）。
- 边：required / optional / incompatible / embedded。
- 计算：直接前置、传递闭包、反向依赖、循环、缺失节点。
- 版本范围：先做基础解析，无法判断时标 `unknown`。

验收：

- 给定 A→B→C，`deps(A)` 返回 B、C。
- `dependents(C)` 返回 B、A。
- 缺失前置进 `missingDeps`。

### 1-6 图数据 + 分类分组

任务：

- 节点：mod / 缺失前置 / 资源条目。
- 边：`required`（实线）、`optional`（虚线，代表联动/可选）、`incompatible`（红色虚线）、`embedded`（点线）。
- 节点颜色：主分类；形状：内容 mod 圆形、前置库方形、优化菱形。
- 节点大小：包内被依赖数（入度）的平方根；枢纽一眼可见。
- 分类分组：用于图例和筛选，不再作为唯一层级。
- 特殊节点：未分类、标签冲突、缺失前置、重复 mod、孤立节点。

验收：

- graph JSON 可直接被前端渲染。
- 能看出：枢纽 mod、只被依赖的前置、既是前置又是玩法的 mod、孤立 mod、缺失前置。
- 手工标签优先于来源标签，但不删除来源标签。

### 1-7 交互式图报告

任务：

- 单文件 HTML，内嵌 JSON，不依赖外部 JS。
- 视觉：极简黑白纸质文件感；米白纸张、墨线、衬线标题、等宽元数据、细线框、点阵网格；不使用彩色，重点靠节点大小、线型和标签表达。
- 布局：桌面三栏；手机竖屏图占满 + 底部详情；手机横屏图占满 + 右侧详情抽屉，筛选左侧滑出。
- 力导向布局：边吸引、节点排斥、分类中心轻微吸引。
- 交互：滚轮缩放、拖拽平移、拖动节点、悬停高亮邻居、点击打开详情。
- 筛选：按分类、边类型、加载器、侧别、是否孤立。
- 详情：来源、标签、直接/传递/反向依赖、问题。
- 提供“只显示依赖”“只显示联动”“只看某分类”快捷视图。

验收：

- 在 cccodroid 文件查看器中打开可用。
- 200–300 个 mod 仍可读；更多时用筛选和聚类降噪。
- 截图能一眼看出主要枢纽和孤立节点。

## 10. P2 详细拆解

### 2-1 工作副本 + edit log

- 导入时复制到 `work/pack/`。
- `modpack-studio.json` 记录原始格式、源路径、标签覆盖、edits。
- 每个 edit 可逆；undo/redo 栈。
- 保存采用临时文件 + 原子替换。

### 2-2 启用/禁用 + 手工标签

- 启用/禁用：`mods/foo.jar` ↔ `mods-disabled/foo.jar`，或项目内状态（导出时处理）。
- 手工标签：写 `tagOverrides[modID]`。
- 改主分类：写 `primaryOverrides[modID]`。
- UI 即时更新，磁盘延迟写入。

### 2-3 卸载

流程：

```text
选择 mod
→ 计算反向依赖
→ 有依赖：弹窗列出依赖者
   [取消] [只卸载] [连同依赖者] [保留]
→ 生成 preview
→ 备份
→ 执行
→ 写 edit log
```

### 2-4 导出

- 保持原格式优先。
- 更新清单：删除/新增 remote 文件条目；重算本地文件哈希。
- 导出到新 ZIP，原包不动。
- 提供“导出变更报告”。

## 11. P3 详细拆解

### 3-1 更新检查

- 对每个有来源的 mod 查可用版本。
- 比较版本、加载器、MC 版本。
- 显示 changelog（若来源提供）。
- 只生成建议，不写文件。

### 3-2 更新执行

- 检查目标版本依赖。
- 检查反向依赖的版本范围。
- 检查加载器/MC 兼容。
- 有冲突则阻止，并给出原因和可选方案。

### 3-3 添加 mod

- 搜索 CF/Modrinth。
- 选版本。
- 递归拉取 required 依赖。
- 预览将添加的文件。
- 用户确认后下载、校验、写入。

## 12. P4 详细拆解

### 4-1 HTTP API + Web UI

API 草案：

```text
GET  /api/v1/health
GET  /api/v1/pack
GET  /api/v1/pack/tree
GET  /api/v1/mods/{id}
GET  /api/v1/mods/{id}/dependencies
GET  /api/v1/issues
POST /api/v1/edits
POST /api/v1/undo
POST /api/v1/redo
POST /api/v1/export
```

约定：

- 只绑定 `127.0.0.1`。
- 启动生成随机 token，前端通过 `?token=` 或 Header 带。
- 所有响应 JSON；错误用 `{ "error": { "code", "message" } }`。
- 版本前缀 `/api/v1`。

### 4-2 单文件分发

```sh
go build -trimpath -ldflags "-s -w" -o modpack-studio ./cmd/modpack-studio
```

- `web/` 通过 `go:embed` 打进二进制。
- 启动参数：`--pack`、`--port`、`--no-browser`、`--analyze`、`--json`。
- 输出启动信息 JSON，便于启动器解析。

### 4-3 启动器适配

- 通用协议：拉起进程 → 读 stdout 的 `{"url":...}` → 打开 WebView/浏览器。
- 适配器只负责找实例目录和展示入口，不碰核心逻辑。
- 后续可做 FCL/PCL/HMCL/Prism 的薄适配。

## 13. 标签体系

### 13.1 一级分类

```text
内容
├─ 科技
├─ 魔法
├─ 冒险/世界生成
├─ 农业/食物
├─ 建筑/装饰
├─ 存储/物流
├─ 装备/战斗
├─ 生物
├─ 任务/进度
└─ UI/HUD

工程
├─ 前置库/API
├─ 优化/性能
├─ 兼容/修复
└─ 数据/配方

资源
├─ 资源包
├─ 光影
├─ 数据包
└─ 脚本

待整理
├─ 未分类
└─ 标签冲突

问题
├─ 缺失前置
├─ 重复 mod
├─ 版本冲突
└─ 加载器不匹配
```

### 13.2 归一化规则

- 保留来源标签原文，不做破坏性合并。
- 维护映射表：`curseforge category -> canonical`、`modrinth category -> canonical`。
- 一个 mod 可以有多个 canonical 标签；`primary` 只用于树的主位置。
- 手工标签优先显示，但不覆盖来源标签。
- 未映射的标签进“其他”，不要丢弃。

### 13.3 标签冲突

出现以下情况标记冲突：

- CF 和 Modrinth 分类完全无交集。
- 一个来源有分类，另一个没有。
- 手工标签与来源标签明显矛盾（如来源全是科技，手工标魔法）。
- 工具启发式判断与来源标签不一致。

冲突只提示，不自动改。

## 14. 依赖图规则

### 14.1 边类型

| 类型 | 含义 | 卸载影响 |
|---|---|---|
| `required` | 必需前置 | 阻止或联动卸载 |
| `optional` | 可选前置 | 提示 |
| `incompatible` | 冲突 | 阻止同时启用 |
| `embedded` | 内置库（JiJ） | 不单独管理 |

### 14.2 计算

- 直接前置：一跳。
- 前置的前置：DFS/BFS 传递闭包。
- 反向依赖：反向图。
- 循环：DFS 检测；循环不一定致命，但要在 UI 标出。
- 缺失：target 无法解析到任何已安装 mod。
- 版本范围：基础 Maven/SemVer 解析；无法判断时 `unknown`，不阻断。

### 14.3 数据来源优先级

1. Modrinth `version.dependencies`（质量最好）。
2. CurseForge `file.dependencies` / `relationType`。
3. jar 内 `mods.toml` / `fabric.mod.json` 的依赖声明。
4. 本地文件名/启发式（最后手段，必须标 `heuristic`）。

## 16. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 启动器格式差异 | 解析失败 | 先做嗅探 + warning，不因未知字段崩溃 |
| CurseForge API Key 缺失 | 无标签 | Modrinth 哈希反查 + 本地元数据兜底 |
| 标签不准确 | 分类误导 | 保留来源标签，显示冲突，不假装权威 |
| 依赖元数据缺失 | 误判安全 | 标 `unknown`，卸载/更新时要求确认 |
| 自动更新破坏包 | 高 | 默认锁版本，只检查，不自动应用 |
| 本地/私货 mod | 无介绍无标签 | 读 jar + 手工标签 |
| JiJ 嵌套 jar | 依赖图缺失 | 第一版不展开，标 `embedded`；后续可选 |
| 大包性能 | 500+ mod 卡顿 | 虚拟列表、懒加载、缓存 |
| 分发权限 | 下载失败 | 尊重 `downloadUrl` 为空，提示用户 |
| 路径安全 | 任意文件写入 | 所有解压/写文件做 canonical 校验 |

## 17. 里程碑与验收

### M1：只读审计可用

- 输入一个真实整合包。
- 输出：格式、MC/加载器、mod 数、依赖/联动图、枢纽、孤立节点、缺失前置、标签冲突。
- 产物：JSON + 静态 HTML。
- 验收：作者能看出“缺哪些前置、哪些没分类、哪些标签冲突”。

### M2：安全编辑可用

- 启用/禁用、手工标签、改分类、卸载。
- 撤销/重做。
- 导出同格式新包。
- 验收：导出的包能被原启动器导入，原包未被修改。

### M3：更新/添加可用

- 检查更新、版本兼容、反向依赖检查。
- 添加 mod 并解析前置。
- 验收：冲突时能阻止并解释原因。

### M4：可嵌入启动器

- 单文件二进制。
- `--pack/--port/--no-browser` 协议。
- 至少一个启动器适配器。
- 验收：启动器一键打开工作台。

## 19. 图优先原型验证（2026-10-30）

为了验证“不要树、要图”的判断，先用真实整合包做了一个只读原型。

输入：

```text
Create Live 5 1.3.2.1
Modrinth / Minecraft 1.20.1 / Forge 47.2.17
95 个文件
```

结果：

```text
节点 95 / 边 71
必需依赖 51 / 可选联动 20
枢纽 4 / 孤立 27 / 前置库 15 / 缺失前置 0
```

被依赖最多：

| mod | 被依赖数 |
|---|---:|
| Create | 26 |
| Just Enough Items (JEI) | 11 |
| KubeJS | 5 |
| Architectury API | 3 |

结论：

1. **Create 是典型“前置也是玩法 mod”**：按分类它只在“科技”，按图它是 26 个 mod 的枢纽。
2. **20 条 optional 边就是联动关系**；树表达不了。
3. **27 个孤立节点**用图一眼可见，适合作者检查“装了但没连线”的 mod。
4. 分类仍有用，但只作为颜色、图例和筛选，不再作为唯一导航。
5. 图优先原型验证通过，后续按本计划把数据层迁到 Go。
